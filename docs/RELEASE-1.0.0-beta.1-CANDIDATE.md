- PR #25 发布制度：日常提交与发版解耦，冻结范围、集中 QA 和单版本安装验证，停止逐个功能发版。
- 自动更新保持关闭；`electron-builder --publish never`。内部测试包不作为公开可信签名包分发。

## A 机升级前（必须顺序执行）

1. 从 B 机记录确切 Git 源码 SHA、NSIS 安装包路径与 SHA-256；不得同名重构安装包后不更新记录。
2. 确认 A 是唯一 `PLIUM` 主进程；正常退出，让 `items.json` 的延迟持久化落盘；不得清空真实剪贴板。
3. 在 **Windows A 本机私有路径**为整个 `%APPDATA%\plium` 创建带日期的全量备份，包含 `Local State`、`items.json`、`payloads`、`images`、`settings.json`；完成逐文件数量/大小/Hash 校验，保留 .10 安装包和旧档案。备份不上传公共仓库、Issue 或聊天。
4. 安装过程中仅保留一个常驻版本；使用已核验 NSIS 文件，不要把 GitHub 上游 Edge-Drop 的安装包用于 PLIUM。
5. 新 v3 会重加密 `items.json`，因此**升级前后密文原始 SHA 不应直接比较为相同**。以备份存在且可回退、条目数量、固定/备注记录、实际内容恢复及功能工作作为验证；若任何项目失败，立即停止后续破坏性操作。

## A 机升级后验收

- 识别 EXE FileVersion、卸载注册表和唯一托盘、单一用户 Session 的主进程；检查开机自启。
- 一行 ↔ 三行反复展开折叠、顶部与侧边停靠、长历史滚动、窗口动画与系统 WER 没有新长时间卡死。
- 真实文本、文件、图片跨应用拖出及图片预览；Esc、搜索焦点、托盘双击与右键菜单、清除历史二次确认。
- 用**合成新记录**验证超长文本、强制终止后的数据恢复；不要主动对真实用户的历史进行破坏性试验。
- 多显示器和不同 DPI（有实际设备时）、冷启动自启和重启一次，核对全部状态，观察使用稳定性。
- 只在用户确认此候选可用后才将它标记为验收完成；正式签名公开发行走下一阶段。

## 回滚说明（高优先级）

**绝对不能只降级 EXE**：旧 v10 不认识新 v3 索引及新的直接 DPAPI 侧文件格式。若要回滚到 v10，必须首先停掉候选版、使用升级前备份**恢复完整旧 profile（包括 Local State 和原始 payloads/images）**，然后安装旧 v10。回滚会放弃升级后产生的新版记录，须先额外留存当前完整新 profile 供手动恢复；不得在用户不知情时覆盖或丢弃新历史。
